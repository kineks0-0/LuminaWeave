# 记忆管理与梦境机制设计 (Memory & Dreaming Architecture)

## 1. 核心定位
本设计为 LuminaWeave 的底层基础设施，提供一套由前端驱动、后端配合的记忆处理 API。
*   **目的**：解决长上下文中的“设定漂移”、“逻辑冲突”以及“信息过载”问题。
*   **适用场景**：制卡工坊 (Forge)、编导插件 (Director)、长线剧情记忆系统。

---

## 2. 三层记忆模型 (The Three-Layer Model)

### 层级一：浅睡 (Shallow Sleep) —— 实时整理
*   **触发条件**：每一轮对话完成。
*   **动作**：
    *   **清洗**：提取 `<Chat_Reply>` 之外的元数据标签。
    *   **归纳**：使用 `XMLInterceptor` 提取 `STORY_SUMMARY` 并进行短期上下文缓存。
*   **目的**：保持近期对话的极高清晰度。

### 层级二：深睡 (Deep Sleep) —— 过滤与固化
*   **触发条件**：消息超出“全量区 (Full Range)”进入压缩区。
*   **动作**：
    *   **筛选**：识别具有核心逻辑权重的条目（如：新产生的设定、重要的关系变更）。
    *   **固化**：将这些条目从 Chat History 中解耦，持久化存储到 Lumina 后端的 `Knowledge_Bank` 或 ST 的 `WorldInfo` 中。
*   **目的**：防止核心设定随上下文滚动而被遗忘。

### 层级三：梦境 (Dreaming) —— 反思与对冲
*   **触发条件**：系统空闲或制卡的关键阶段（如导出的第十三步）。
*   **动作**：
    *   **反思 (Critique)**：利用后台 SSE 流（用户不可见），对比“近期聊天记录”与“全量世界书条目”。
    *   **检测**：识别其中的逻辑矛盾 (Conflict) 或 OOC 倾向。
    *   **产生洞见 (Insight)**：生成改进建议，存储在独立的 `Insight_Store` 中，并作为下一轮对话的高权重提示词注入。
*   **目的**：确保系统的逻辑纯净度。

---

## 3. 焦距模式与内容提权 (Context Focus System)

为了平衡 Context 长度与精准度，采用动态提权策略：
*   **索引模式 (Baseline)**：世界书条目以“ID + 极简摘要”形式存在。
*   **对焦模式 (Focused)**：当前正在编辑或被引用的条目，以“全量原文”形式注入。
*   **触发机制**：
    *   用户直接选中。
    *   模型通过 `<FORGE_SKILL name="FETCH_FULL" />` 主动申请。

---

## 4. 前端驱动的微型 Agent 循环 (Frontend-Led Agent Cycle)

当模型发现信息不足或需要修改时，触发以下闭环：

1.  **主动申请**：LLM 输出 `<FORGE_SKILL name="READ" id="xxx" />`。
2.  **前端拦截**：`StreamingManager` 识别标签，暂停 UI 渲染（或并在状态栏显示中间状态）。
3.  **动态指令回填 (State-Based Override)**：
    *   前端获取全量内容。
    *   前端将 **[全量原文] + [状态指令：请提出修改规划方案]** 作为下一轮的系统输入。
4.  **方案送审 (Review Gate)**：
    *   模型生成 `<DRAFT_PLAN>...</DRAFT_PLAN>`。
    *   前端渲染出 Diff 对比界面，由用户决定“同意”或“打回”。
5.  **最终落地**：用户同意后，前端触发第三次生成，模型输出 `<ENTRY_UPDATE>` 正式修改内容。

---

## 5. 存储架构建议
*   **对话流存储**：基于 ID 链的 JSONL。
*   **梦境洞见库**：KeyValue 结构，存储条目间的生克关系与潜在矛盾。
*   **角色/世界蓝图**：基于“基元 (Primitives)”的树状结构。
