# LuminaWeave (幻光织机) - 架构与功能规划 v3.6

**定位**：SillyTavern 生态的下一代增强框架与综合体验操作平台。

_“以幻光为引，折射并编织无限的世界线。”_

## 一、 项目愿景

**LuminaWeave** 旨在彻底改变玩家在 SillyTavern 中的交互方式。它不仅仅是一个美化界面的插件，而是一台能够掌控对话走向、重塑角色记忆、管理平行宇宙的“织机”。通过解耦的模块化设计，它为用户提供现代化的流畅界面，同时默默接管底层复杂的事件流、模型调度与**全局状态演算**，让“跑团/角色扮演”体验达到前所未有的高度。

## 二、 核心功能规划 (用户体验层)

LuminaWeave 包含多个可独立开关的官方子插件，共同构建完整的沉浸式体验：

### 1. Lumina Timeline (幻光时间线：视觉小说级多维世界线)

彻底颠覆 ST 原有的“只退不进”的线性聊天。

- **Git 化分支导航图**：将漫长的对话历史转化为标准的 **Git 风格多轴轨道图**。用户可以清晰看到每一次“重新生成”或“改变回复”所产生的多轴分支，并通过颜色区分不同的平行路径。
    
- **智能分支剪枝 (Zero-noise Pruning)**：侧边栏模式下仅全量展示活跃路径，非活跃分支仅保留首层入口节点，彻底解决复杂逻辑下的 UI 拥堵与卡片重叠。
    
- **状态感知的世界线跳转**：当用户在图中点击“穿越”回过去的某个节点时，不仅聊天记录会切换，角色当时的心情、物品栏状态、当前场景都会被完美回溯。
    
- **多分支保留**：随时回到历史节点开辟新对话，原有的时间线将被永久保留，用户可以在不同的平行结局中自由穿梭。
    

### 2. Lumina Memory (幻光记忆：主动回想与图谱记忆)

解决长篇对话中 AI 常见的“失忆”和“逻辑混乱”问题，极大降低用户的调教心智负担。

- **对话规则动态追加**：用户可以在聊天中自然地输入指令（如 `/rule 从现在起你受伤了`），该规则将**仅绑定在当前及后续的世界线节点**上，不会污染过去的分支。
    
- **语义切章与主动检索**：系统会自动将万字长文切分为“章节”。当 AI 遇到遗忘的细节时，引擎允许 AI “暂停思考”，主动去记忆库中翻找特定章节，再给出完美答复。
    
- **关系图谱提取**：后台静默将复杂的剧情提炼为人物关系网（如“A 赠送 宝剑 给 B”）。当提起宝剑时，系统直接将这条极其精简的逻辑发给 AI，彻底根治长线跑团中的逻辑矛盾。
    

### 3. Lumina Forge (幻光工坊：高级制卡与偏好管理)

提供一个独立、美观的全屏制卡器面板。

- **偏好矩阵预设**：用户可以保存多套“预设组”（包含特定的系统 Prompt、越狱指令、生成参数等）。
    
- **一键套用**：新建卡片时，一键应用最爱的偏好矩阵，并直接作为整条时间线的“根节点规则”生效。
    

### 4. Lumina Status (幻光状态栏：动态感知面板)

为硬核跑团和沉浸式扮演提供一个悬浮/固定的可视化 UI 面板（展示 HP、好感度、物品栏、时间等）。

- **纯粹的数据消费者**：本插件不再负责复杂的指令解析，而是纯粹基于底层框架提供的“全局状态树”进行UI渲染。
    
- **无缝 UI 动效**：当底层通知数据发生增量更新时，状态栏对应的词条会触发高亮的 UI 刷新动效（如数值扣血变红、物品栏图标翻转）。
    
- **自动时空回溯**：由于数据交由核心层 FSM 托管，当你在 Timeline 中穿越回过去的节点时，状态栏面板会自动“逆向撤销（Rollback）”，物品和血量瞬间恢复原样。
    

### 5. Lumina Nexus (幻光枢纽：高自由度请求编排与模型分流)

彻底终结多插件并发请求带来的卡顿与高昂 Token 消耗，把向大模型索取数据的“组装权”完全交还给用户。

- **高度自定义的请求编排面板**：系统提供一个直观的路由配置界面，用户可以像拼图一样，自由决定哪些插件的请求合并，哪些独立发送（例如：主线回复、状态增量指令、图谱提取 全部合并为一次请求）。
    
- **模型与预设的自由分配**：每个“请求组”都可以独立指定调用的模型。例如主线用 `Claude 3 Opus`，后台提取状态用本地 `Gemini Flash`。
    

### 6. 体验韧性增强 (无缝交互体验)

通过接管底层网络与请求，解决日常使用中的痛点：

- **息屏不断连 (响应缓冲池)**：在手机端使用时，哪怕切到后台或锁屏导致网络断开，后端的缓冲池依然会静默接收 AI 的长篇回复。再次打开界面时，瞬间完整加载。
    
- **无痕指令控制 (挥发性指令)**：用户想给 AI 发送临时系统指令（仅在当前请求生效，绝对不会写入聊天记录中），保持界面纯净且保护 API 上下文缓存。
    

## 三、 界面设计与交互范式 (UI/UX Design) **[NEW]**

为了支撑复杂的功能而不增加视觉负担，LuminaWeave 的 UI 设计采用“现代、轻量、基于上下文”的原则。根据用户的操作场景，界面支持两种无缝切换的展现形态：

### 1. 沉浸伴随态 (Split-Pane / Sidebar Mode)

**适用场景**：日常聊天、沉浸式角色扮演。

- **布局逻辑**：保留 ST 原生的左中区域作为“主聊天流（Chat Stream）”，LuminaWeave 仅以“侧边栏（Sidebar）”或“顶/低部注入区”的形式半展开，不喧宾夺主。
    
- **状态栏注入 (Top Bar Injection)**：在界面的顶部或聊天框上方，横向注入精简版的 `Lumina Status`（如线性的 HP 条、好感度百分比、当前时间），数值发生增量变动时伴随轻柔的呼吸灯或数字跳动特效。
    
- **右侧伴随时间线 (Mini-Timeline Sidebar)**：右侧半展开一个折叠面板，显示基于 **Git 轨道算法** 渲染的垂直 Timeline。结合 Zero-noise 剪枝策略，确保高密集的对话分支依然清晰可辨。
    

### 2. 全景掌控态 (Full-Canvas Expanded Mode)

**适用场景**：复杂世界线回顾、历史节点跳跃、请求路由编排（Nexus）。

- **布局逻辑**：点击“展开”按钮后，ST 原生聊天流被覆盖，整个屏幕由 LuminaWeave 提供重构后的聊天界面，左边为聊天记录，右边为插件提供界面，可以单个或者多个，比如状态栏+世界线，顶部提供切换栏，切换至子插件其他全屏界面（比如世界线等），状态栏mini展示，设置。
    
- **世界线宏大节点树 (Node Tree Explorer)**：像《底特律：变人》一样的横向/发散型树状图占满全屏。用户可以在这里上帝视角俯瞰所有的平行宇宙，拖拽节点连接线。
    
- **可视化请求编排 (Visual Orchestrator)**：在 Nexus 模块中，这块画布展示为数据流节点（如：节点 A 代表模型生成，节点 B 代表状态更新，用连线表示它们是合并请求还是异步请求）。
    
- **悬浮快捷聊天 (Floating Quick Chat)**：为了防止用户在其他面板中丢失扮演上下文，当点击任意一个历史树节点/其他子插件全屏界面时，画布右下角会弹出一个类似手机聊天窗口的悬浮浮层（Quick Chat）。用户可以在全页面展开的画布上，直接在悬浮窗中与该节点发生试探性对话，满意后再将其确立为主世界线。
    

## 四、 底层技术基座：Lumina Core

为了支撑上述宏大的功能与 UI 规划，Lumina Core 作为微内核，提供了坚实且安全的底层架构：

### 1. 细粒度生命周期网关 (Granular Event Prism)

不再是粗放的事件拦截，而是将对话生成拆解为极其精确的管道，方便子插件挂载：

- **[Prompt 构建期]**：`[核心设定初始化]` -> `[世界书/图谱织入]` -> `[当前节点动态规则织入]` -> `[格式化排版]`
    
- **[请求与接收期]**：`[请求发送前 (无痕指令注入点)]` -> `[打字机流式接收]` -> `[正则处理后]` -> `[渲染前处理]`
    

### 2. 安全的 UI 宿主引擎 (Shadow DOM 沙盒)与核心插件系统 (PluginManager)

- **UI 隔离**：摒弃粗暴的全局 UI 接管。无论是“伴随态的侧边栏”还是“悬浮的快捷聊天窗”，LuminaWeave 都会在对应的挂载点开辟 **影子 DOM (Shadow DOM)** 隔离区，完美免疫旧版 jQuery 插件引发的全局样式冲突与 VDOM 覆盖崩溃。
- **插件化解耦 (Plugin System)**：采用极致松耦合的 `PluginManager` 架构，将聊天流 (`ChatRegion`)、世界线 (`Timeline`)、状态指示器 (`Stats`) 统统抽象为独立注册的 Plugin。UI 主干 (`App.vue`与`PanelHeader.vue`) 成为纯粹的渲染插槽池 (`slots`: `mainView`, `widget`, `headerRight`)，极大降低了长期演进的代码腐化风险。

### 3. 状态投影与影子数据库 (Shadow Buffer & Event Sourcing)

- **影子数据库隔断原生依赖**：底层引擎通过 `api/index.js` 中的 `localChatData` 做桥接。原生环境爆发的 DOM 突变（例如流式写入、重生成闪烁）不再粗暴驱动本框架的 UI。
- **选择性同步 (Selective Sync)**：在 Timeline 插件进行时间线跳跃或分支编辑时，绝对不强行覆写原生系统的数组内存；所有编辑 (`edit`, `delete`) 只发生在影子数据库中。直到需要大模型介入时，才通过事务函数 `commitToST()` 安全组装并“注入”给原生环境。
- **不可变日志**：系统维护一个只增不减的历史事件日志（包含聊天事件与状态变更事件）。跳转分支时，通过计算出当前活跃分支的“投影 (Projection)”，恢复所有变量，让原生系统误以为当前只存在一条线性聊天记录。
    

### 4. 同构 RPC 跨进程通信

打通浏览器前端 (UI) 与 Node.js 后端 (Server) 的物理壁垒。前端的全景画布可以直接呼叫后端的图谱查询数据库，后端也能直接指令前端触发特定的 UI 动效。

### 5. 高自由度任务路由引擎 (Customizable Task Routing)

为插件提供极致解耦的 LLM 调度能力：

- 子插件仅通过 `requestTask({ schema })` 提交其数据需求池，不再直接触碰网络层。
    
- 核心引擎拦截所有任务，根据用户配置的路由表（如合并挂载 Piggyback 或 独立批处理 Batching）自动生成 Prompt、发送请求、并在接收后自动拆解分发数据。
    

### 6. 统一增量更新引擎 (Incremental State Engine)

将状态的修改权限收归底层 FSM (有限状态机)，作为所有插件的公共基础设施。

- **全局状态树 (Global JSON Tree)**：维护一个独立于聊天记录的结构化数据树（可供状态栏、任务面板、好感度系统等所有插件共用）。
    
- **高精度原子操作集**：引擎强制大模型输出极低开销的“增量 Patch 指令”，而非重写整个状态。支持标准化的指令如：
    
    - **修改**：`Modify("status.health", "轻伤")`
        
    - **按索引更新**：`Update("inventory[1]", "被咬过的苹果")`
        
    - **增删**：`Add("inventory", "神秘钥匙")`，`Remove("inventory", "铁剑")`
        
- **解析与广播机制**：在 `reply_receive` 阶段，引擎截获模型生成的原子指令，静默更新全局状态树，并向相关的子插件（如 Lumina Status）派发 `STATE_MUTATED` 事件触发 UI 重绘。它与事件溯源（Event Sourcing）天然结合，完美支持任意时间节点的瞬间回溯。
    

## 五、 开发演进路线图 (Roadmap)

按照功能价值交付的优先级排列：

- **阶段 1-19：基座破壁与时间线筑基 (✅ 已完成)** 
  - 建设 Lumina Core 细粒度网关与 RPC 桥接。
  - 落实 Shadow DOM 宿主引擎与双模式（沉浸伴随侧栏 / 全景画布）界面切换。
  - 落地 `Lumina Timeline` Git 化多轴渲染引擎与小窗导航，支持复杂的横向交汇、轨道动态计算、分支剪枝方案。
- **阶段 20-21：深度架构解耦与本地数据代理 (✅ 已完成)**
  - 实施 `PluginManager`，彻底分离核心与四组内置插件 (`Chat`, `Timeline`, `Stats`, `Settings`)。
  - 构建独立于 ST Core `window.chat` 的本地影子数据库，达成 “修改/跳跃/重生成仅对本插件发生 -> 确认后再下沉回 ST 原生缓冲” 的单向流。彻底根治多平台融合带来的滚动卡顿和视图撕裂。
- **阶段 3：状态机制接入 (🚧 开发中)** 
  - 引入 `Lumina Status`，依托底层状态 FSM 提供数值更新高亮、UI 重绘。
- **阶段 4：记忆图谱与逻辑赋能** 
  - 引入 `Lumina Memory`，实现节点动态规则无缝绑定，提取角色逻辑长效记忆图谱。
- **阶段 5：幻光枢纽完善**
  - 不做强制接管，提供高级图形化拖拽节点配置网关界面 (`Lumina Nexus`)，打通不同模型、请求链路分流的终极用户自由度。
- **阶段 6：工坊与进阶功能探索** 
  - 独立全屏制卡器与偏好矩阵矩阵模板生成工具。
