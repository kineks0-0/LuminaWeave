# LuminaWeave 文档规范

本文规定 LuminaWeave 应维护哪些文档、放在哪里、什么时候更新。目标是让新协作者先读文档就能理解系统边界、找到接口、判断改动是否需要同步更新设计。

## 1. 文档体系总览

| 文档 | 位置 | 什么时候更新 |
| ---- | ---- | ---- |
| 仓库 README | `README.md` | 项目定位、快速开始、目录结构或文档入口变化时 |
| 文档入口 | `docs/index.md` | 文档目录、任务入口、归档入口变化时 |
| 短版架构入口 | `docs/architecture.md` | 架构边界、依赖方向或核心运行层级变化时 |
| 全局 PDR | `docs/overall/PDR.md` | 产品定位、核心功能目标或长期能力变化时 |
| 全局 System Design | `docs/overall/system_design.md` | 核心系统设计、数据流、生命周期或模块边界变化时 |
| 模块文档 | `docs/overall/modules/<module>/` | 模块职责、接口、状态或 UI 行为变化时 |
| API 参考 | `docs/overall/api/` | 对外 API、请求响应、错误语义变化时 |
| 设计规格 | `docs/overall/design/` | 视觉系统、桌面模式、组件规范变化时 |
| 当前任务 | `docs/current/tasks/<task>/` | 长周期任务开始、推进、暂停或恢复时 |
| 归档任务 | `docs/archive/completed-tasks/<task>/` | 当前任务完成并沉淀验证记录时 |
| 配置参考 | `docs/configuration.md` | 构建脚本、宿主安装、运行配置或环境要求变化时 |
| 存储与数据 | `docs/storage-and-data.md` | 持久化格式、数据目录、事务日志、迁移策略变化时 |
| 测试与 CI | `docs/testing-and-ci.md` | 测试策略、验证命令、CI 要求变化时 |
| 协作指南 | `docs/contributing.md` | 分层边界、开发流程、提交规则变化时 |
| ADR | `docs/adr/` | 做出重大架构或技术取舍时 |

硬规则：改了公共 API、存储结构、生命周期、数据流或模块职责，必须同次更新对应文档。

## 2. 目录规则

- 长期有效的产品、架构、API、模块和设计规格进入 `docs/overall/`。
- 正在执行或仍需恢复上下文的任务进入 `docs/current/tasks/<task-name>/`。
- 已完成任务整体移动到 `docs/archive/completed-tasks/<task-name>/`。
- 每个模块目录应提供 `README.md` 作为入口；已有 `PDR.md` 和 `system_design.md` 保留为深层文档。
- 移动 Markdown 文件后必须修复仓库内相对链接。

## 3. 文档写法

- 统一使用中文。
- 先讲边界，再讲细节；先说明“这页解决什么问题”，再进入字段、流程或接口。
- 长文档按“是什么 / 为什么 / 输入 / 处理流程 / 状态变化 / 输出 / 上下游影响 / 已知限制”组织。
- Mermaid 或 ASCII 图优先于截图；截图不可搜索，不能作为唯一说明。
- 不把阶段性执行记录长期堆在 PDR 或 System Design；执行记录应进入 `docs/current/` 或 `docs/archive/`。
- 不写未落地能力为已实现事实；无法验证的内容必须标注“待确认”或“规划中”。

## 4. API 文档模板

每个 API 资源页开头应说明：

- 这组接口做什么。
- 什么时候需要看这页。
- 关键术语。
- 一个最小调用例子。

每个接口至少包含：

- 方法与路径。
- 用途说明。
- 路径参数、查询参数、请求头、请求体。
- 成功响应示例。
- 错误码与业务错误语义。
- 最小 curl 示例。

如果某个接口仍未从源码确认，不要补虚构字段；先写“待源码确认”。

## 5. 存储文档模板

每种持久化格式至少说明：

- 事实源是什么。
- 谁写入，谁读取。
- 文件或 key 的位置/命名规则。
- 迁移或兼容策略。
- 是否允许提交到 Git。
- 出错时的恢复方式或风险边界。

## 6. ADR 规则

以下情况应新增 ADR：

- 架构分层或依赖方向变化。
- 宿主适配策略变化。
- 存储格式或迁移策略变化。
- Prompt 合成管线、资源引用、事务协议的重大取舍。
- 公共插件 API、桌面模式 API 或 surface contract 的破坏式变化。

文件名格式：`NNNN-short-title.md`。状态使用：`已采纳`、`提议中`、`已废弃`、`已被 ADR-XXXX 取代`。
