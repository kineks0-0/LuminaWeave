# 阶段 4：自定义桌面标准化 API

## 目标

建立正式的自定义桌面扩展协议，让其他开发者可以在不越权修改核心运行时的前提下，注册并接入自己的桌面模式。

## 输入与前置条件

- 前三阶段已完成，桌面模式已稳定为单轴模型
- 内置模式与运行时解析链路已经统一在 `activeDesktopMode`
- 设置系统已经能够按桌面模式组织详情展示

## 需要修改的子系统

- `luminaweave-extension/src/theme/*` 注册中心与公开类型
- 桌面模式列表与设置详情区的自动接入逻辑
- 运行时桌面模式解析逻辑
- `docs/overall/api/luminaweave_api.md`

## 明确输出

- 新增正式注册入口 `registerDesktopMode()`
- 定义 `DesktopModeManifest` 最小字段与约束
- 让第三方注册的模式自动进入：
  - 桌面模式选择列表
  - 设置详情区
  - 运行时模式解析
- 在 `docs/overall/api/luminaweave_api.md` 新增“自定义桌面模式开发”章节
- 明确越权边界与受控 renderer variant 规则

## 禁止事项

- 不允许让 manifest 直接替换核心会话、同步、持久化接口
- 不允许开放无约束的任意运行时代码覆写
- 不允许要求第三方为设置页再写一套手工接线逻辑
- 不允许通过兼容旧模型牺牲新协议清晰度

## 验收检查

- 本地插件可在初始化时注册一个自定义桌面模式
- 注册后无需手补设置页代码即可显示
- 重复 id 会被拒绝
- 核心运行时接口不可被桌面模式 manifest 直接替换
- `npm run type-check` 通过

## 完成后才能进入下一阶段的条件

- 桌面模式扩展 API 已形成稳定文档和最小实现闭环
- 自定义模式的注册、显示、解析链路已打通
- 核心运行时边界已经在类型和文档层被明确约束
