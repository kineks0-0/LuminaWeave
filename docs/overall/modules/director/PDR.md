# SillyTavern 深度编排引擎 (Project Director)

## 第一部分：产品需求文档 (PRD)

### 1. 定位

一款脱离 SillyTavern (ST) 原生生成限制，自带 API 路由分流、Vue/TS 响应式状态管理、多级记忆与主动剧情推演的 Agent 级别调度插件。

### 2. 核心模块与业务逻辑

#### 2.1 混合调度路由 (Hybrid LLM Gateway)

- **路由分发**：支持用户配置多个 API 端点（主线模型、后台总结模型、高容错备用模型）。
- **双轨请求**：支持在一次对话中**合并请求**（剧情规划+对话生成），也支持在后台开启**独立请求**（异步处理记忆总结和深层检索）。

#### 2.2 导演/剧情策划子系统 (Director Subsystem)

设置两种核心工作模式，以应对不同的算力预算和剧情复杂度：

- **轻量模式 (Piggyback / 合并请求模式)**：
  - **机制**：不单独发请求，而是合并到常规对话请求中。
  - **闭环逻辑 (Plan -> Execute)**：
    1. **本次请求**：要求 AI 在输出角色对话的同时，在末尾附带 `<Next_Plan>下一步剧情规划/动作指导</Next_Plan>`。
    2. **下次请求**：将上次的 `<Next_Plan>` 作为**前置约束**，结合用户的最新输入，指导 AI 构思当前回合的剧情发展并输出对话内容。
  - **特点**：省 Token，响应快，适合连贯的短线动作推演。
- **重量模式 (Async / 独立后台请求模式)**：
  - **机制**：由特定条件（如场景切换、关键事件触发、累计N轮对话）触发的后台独立请求。
  - **闭环逻辑**：专门调用一个逻辑能力强的模型（如长上下文模型）来梳理长线剧情、检索历史图谱，并将宏观的“章节大纲”更新至长期记忆中。

#### 2.3 分层记忆系统 (Layered Memory System)

- **Tier 0 (核心灵魂)**：常驻 System Prompt，包含核心人设和世界观。
- **Tier 1 (结构化状态)**：由插件 Vue Store 维护的动态数据（物品栏、关系网）。
- **Tier 2 (近期记忆)**：最近 N 轮的本地对话内容。
- **Tier 3 (概况记忆)**：近期剧情的摘要总结。
- **Tier 4 (历史档案)**：需要通过重量模式主动检索的深层背景或远古记忆。

#### 2.4 记忆系统的更新机制 (Memory Update Mechanisms)

记忆如何更新？系统同样采用“双轨并行”的维护模式：

- **模式一：轻量模型驱动 (AI-Driven Mutation)**
  - 依赖主对话模型在输出时携带特定 XML 标签（如 `<Memory_Update>`, `<Inventory_Change>`）。
  - 插件拦截这些标签后，直接修改 Vue Store 中的状态变量，从而在下一回合改变 Prompt 组装的内容。
- **模式二：插件自动维护 (Plugin-Automated Maintenance)**
  - **滑动窗口**：插件自动管理 Tier 2（近期记忆）的队列，剔除最早的对话。
  - **生命周期清理**：插件自动判断数据的“保质期”（例如上一回合的 `<Next_Plan>` 在本回合使用完毕后，插件会自动将其从缓存中抹除，不写入历史记录）。
  - **自动总结**：当对话轮次达到阈值时，插件在后台静默发起请求，将 Tier 2 压缩归档到 Tier 3。

## 第二部分：系统设计与架构 (System Design)

### 1. 架构流图 (Architecture Data Flow)

```
[用户输入] ──> [插件核心拦截层] ──> 获取当前分支/时间线节点
                    │
                    ▼
          ┌───────────────────┐
          │   Prompt Builder  │ <──(严格依照数据优先度组装)
          └───────────────────┘
            │               │
  [前置插槽 Pre-Context]   [后置插槽 Post-Context]
  - 优先级：极高           - 优先级：低/功能性
  - 核心世界观/人设        - 状态栏(仅供AI参考时)
  - 上回合 <Next_Plan>     - 本地对话内容剧情总结要求
  - 关键人物关系/好感度    - XML 格式强制输出规范
            │
            ▼
        [LLM Gateway] ──(重试机制/多API支持)──> 大模型
            │
            ▼
      [XML 拦截与解析器 (Interceptor)]
            │
      (根据数据标识与生命周期分流)
      ├─ 分析丢弃类: <Thoughts> -> 仅用于 AI 自我推演，解析后丢弃
      ├─ 下次必需品: <Next_Plan> -> 存入 DirectorStore，供下回合使用，随后销毁
      ├─ 写入上下文: <Chat_Reply> -> 作为近期记忆 (Tier 2) 持续存留
      ├─ 状态持久化: <Inventory_Add> -> 触发 Vue Store 更新 (Tier 1)
      │
      ▼
   [文本清洗 Text Cleaner]
      │
      ▼
[ST Chat UI (纯净渲染)]
```

### 2. Prompt 插槽化组装与数据优先度 (Data Priority & Slots)

为了保证 AI 严格遵循指令，数据必须按照逻辑优先级插入不同的 Prompt 插槽：

#### 2.1 前置插槽 (Pre-Context / High Priority)

放置**必须指导当前对话生成**的先决条件。

- **Tier 0 核心设定**：绝对不能违背的规则。
- **剧情规划 (上回合的 `<Next_Plan>`)**：AI 必须据此构思本次回复的走向。
- **重要结构化数据**：影响判定的物品或重大人际关系突变。

#### 2.2 核心对话插槽 (Chat History)

- **Tier 2 近期记忆**：最近的 N 条聊天记录，提供语境连贯性。
- **User Input**：用户当前的最新输入。

#### 2.3 后置插槽 (Post-Context / Low or Task Priority)

放置**无关紧要的参考数据**或**本次生成的输出规范**（大模型对末尾的指令依从性最高）。

- **次要状态栏**：不严重影响剧情，仅作背景参考。
- **总结任务指令**：如果本回合兼顾“轻量总结”任务，要求 AI 在末尾输出总结。
- **输出格式锁**：强制要求输出 `<Next_Plan>` 和特定 XML 的系统指令。

### 3. 数据标识与生命周期管理 (Data Lifecycle & Tagging)

插件需要明确识别模型返回的数据属于哪种生命周期，并以此决定它们是否进入记忆系统：

| **数据标识 (XML Tag)**         | **性质定义**                    | **记忆系统处理方式 (Lifecycle)**                             |
| ------------------------------ | ------------------------------- | ------------------------------------------------------------ |
| `<Thoughts>...</Thoughts>`     | **分析与推演** (与对话文本无关) | **阅后即焚**。插件解析后直接丢弃，不写入 ST 聊天记录，绝对不进入 Tier 2 近期记忆，防止思维链污染上下文。 |
| `<Next_Plan>...</Next_Plan>`   | **单回合必需品** (为了下次对话) | **临时挂载**。存入 `DirectorStore`，在下一次生成请求时塞入前置插槽。一旦下一次请求完成，该条规划即被**覆写或销毁**。 |
| `<Chat_Reply>...</Chat_Reply>` | **核心对话内容**                | **写入上下文**。剥离 XML 标签后，作为纯文本推入 ST 聊天记录界面，并自然流入 Tier 2 (近期记忆) 队列。 |
| `<Inventory_Change>` 等        | **状态持久化** (结构化突变)     | **修改引用源**。不保留标签本身，但触发 Vue Store 数据的 CRUD 操作。更新后的数据会在未来的所有请求中，以表格/列表形式重新映射到 Tier 1 插槽中。 |

### 4. 容错与重试机制 (Error Handling & Retry)

1. **初次解析**：捕获大模型返回的全文。
2. **正则/DOM 提取**：提取 XML 节点，并根据生命周期表（上表）分发。
3. **校验逻辑**：如果发现标签未闭合，或试图向 `Inventory` 中添加非法数据格式。
4. **挂起与重试**：
   - 挂起本次 UI 渲染，不展示给用户。
   - 将错误信息转化为系统提示词（如：`"Error: XML formatting failed at <Next_Plan>. Please output properly closed XML tags."`）。
   - 携带此提示词，通过 `LLM Gateway` 重新发起静默请求。
   - 可设定最大重试次数（如 2 次），失败则回退给用户干预。
