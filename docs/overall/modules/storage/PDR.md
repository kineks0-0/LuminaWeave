# LuminaWeave Storage 组件 - 产品需求文档 (PDR)

**版本:** v1.0
**所属系统:** LuminaWeave V2 Core API

## 一、 定位与愿景
随着界面的独立，本地产生的对话、设置项以及状态需要一种比默认 `extension_settings` 更加灵活的管控。
`Storage` 机制作为底层核心 API 提供给全平台，它的愿景是：一套数据（无论它是排版大小，还是完整的历史聊天记录）都能由用户随心所欲地控制“存放域”和“生效范围”。 

## 二、 核心功能：数据存放架构与作用域 (Scope & Storage)
支持对每一个键值或数据集定义以下五种作用域规则：

1. **全局 (Global)**：始终不变，所有角色、所有聊天记录共享。
2. **跟随角色卡 (Follow Character)**：针对每一个独立的 Character 卡片独立存储（例如：为角色 A 保存大字体和特定血量，为角色 B 保存小字体）。切换角色时自动应用。
3. **跟随对话 (Follow Chat)**：绑定于当前特定的 Chat ID，同一角色开新档时不继承。
4. **仅当前浏览器存储值 (Memory/Session Only)**：数据刷新即挥发，不写入长久数据库，绝对不污染 ST 存档文件（适用于不想保存的测试变量）。
5. **自定义规则 (Custom Rule)**：用户可在此后挂载 JS 脚本或者基于特定的逻辑条件返回，实现极客级的高自由定制。

## 三、 使用场景
- **配置数据注入 (Settings)**: Settings 模块成为该 API 的消费者。各个插件在注册时只需宣告它们拥有哪些配置项，并声明它们的默认值和“不可用作用域”(例如某项系统主题配置被禁止设为“跟随角色”)。
- **对话数据下沉 (Chat Data)**: 原本绑定在 ST 原生 `chat` 数组内的记录，现在可通过此 API 定义其存储域，比如“存储到单独的扩展数据中”、“仅作为临时 Session 试探保存”、“通过挂载桥接编码存入世界书”等。 

## 四、 插件接口极简原则
各个子插件不需要自己写繁琐的存取逻辑。只需要在 `PluginManager` 注册表中申明：
- `defaultValues`: `{ fontSize: 16 }`
- `disabledScopes`: `['Custom Rule']`
所有读、写、监听数据变化的回调全部由本 Storage API 在后台代理并执行。

## 五、 未来扩展：Phase 23 全栈混合架构 (Hybrid Webpack Migration)
为了实现 `LuminaWeave.json` 这类完全独立配置的物理持久化，未来不仅限于前端 `extension_settings`。我们将采用 `express` 后端 Node.js 端点配合 Webpack 前端资源，组合为一个只需用户“一次安装”的混合全栈大架构。所有的前端持久化保存请求将直接发送到专属的独立后端 JSON 文件网关。
