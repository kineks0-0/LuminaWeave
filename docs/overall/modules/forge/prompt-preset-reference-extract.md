## 2. 可迁移能力模块

### 需求捕捉

目标：

- 从显性需求外继续识别隐性偏好、情绪价值、禁忌点、体验目标

落地方式：

- 主模型优先识别“用户到底想玩什么”
- 在制卡设计中把需求拆成可执行的支撑点，而不是只做抽象总结

### 性癖 / 欲望捕捉

目标：

- 多维度拆解标签、关系、氛围、身体感受、触发条件、边界

落地方式：

- 仅作为附加条目保留
- 默认关闭
- 强调抽象化、机制化、可迁移，不把其写成唯一默认方向

### 反八股

目标：

- 避免套话、避免空洞总结、避免模板化比喻和偷懒描写

落地方式：

- 主模型：避免输出泛化建议和平均化结论
- 执行模型：避免把原条目磨平成模板腔
- 测试聊天：避免对白和描写像“说明书”

### 偏向强化

目标：

- 把用户已显露的偏好放大，而不是平均化处理

落地方式：

- 主模型在判断制卡方向时优先保留真正吸引用户的部分
- 执行模型在重写时优先强化已存在的亮点
- 测试聊天在对戏时优先围绕已释放的兴趣点推进

### 专业化 / 去拟合

目标：

- 优先结构、机制、支撑点、可执行描述，不迎合空泛模板

落地方式：

- 主模型强化“交互范式 / 美学纲领 / 实现机制”视角
- 执行模型强化“保意图重写”和“压缩冗余”

### 文风强化

目标：

- 强化细节密度、对白生活感、场景 / 五感 / 动作的具象化

落地方式：

- 测试聊天优先使用
- 执行模型在不改变目标的前提下提升质感
- 主模型只吸收其“判断标准”，不让制卡说明文案过度文学化

## 3. 三类 Profile 的接入建议

### 主模型

定位：

- 偏“需求拆解 + 制卡方向判断 + 设计支撑点”

接入策略：

- 保留原有 slot 顺序
- 在 `base_system_prompt` 后追加 2 个默认启用的自定义 system 条目：
  - `需求捕捉与支撑点识别`
  - `反八股与偏向强化`
- 追加 1 个默认关闭的 XP 附加条目

说明：

- 该组条目只强化上层行为，不覆盖 Forge 既有协议

### 执行模型

定位：

- 偏“重写时保留核心意图 + 提升质感 + 去套话”

接入策略：

- 保留原有 slot 顺序
- 在 `base_system_prompt` 后追加 2 个默认启用的自定义 system 条目：
  - `保意图重写规则`
  - `去套话 / 去空泛 / 提高清晰度`
- 追加 1 个默认关闭的 XP 质感强化附加条目

说明：

- 执行模型只负责重写，不负责任务扩写

### 测试聊天

定位：

- 偏“对戏可玩性 + 对白活人感 + 偏好显化”

接入策略：

- 继续使用 `composed` engine
- 不改角色卡来源逻辑，保持 `from_st`
- 在角色卡与世界书 slots 之前插入 2 个默认启用的 system 条目：
  - `测试聊天行为导向`
  - `反八股 / 活人感对白`
- 追加 1 个默认关闭的 XP / 性癖捕捉附加条目

## 4. 使用说明

- 这组“参考提炼”预设是新增内置预设，不会替换当前默认绑定
- XP 向条目默认关闭
- 因为内置预设不可直接编辑，如需启用 XP 条目：
  - 先在 Prompt 预设工作台中复制该内置预设
  - 再在副本中开启对应条目
