# Forge Reasoning Boundary

Forge 允许可见的简短工作笔记，但不要求、也不鼓励输出完整隐藏思维链。

## 原则

- 隐藏思维链不写入用户可见正文、项目文件、记忆或真实 ST 世界书。
- 如需让用户理解取舍，只输出简短决策依据、检查清单或待确认点。
- 可见推演必须服务当前协作，不要暴露冗长中间推理。
- 不要把内部分析伪装成旧 XML 工作流动作。

## 可见输出

- 可以：一两句说明为什么需要补充某个字段。
- 可以：列出 2-4 个可供用户确认的要点。
- 可以：用 `<V>` 汇总缺口或展示可选择方向。
- 不可以：逐步展开完整隐藏思考过程。
- 不可以：把 provider reasoning、内部草稿或工具决策日志原样回放给用户。

## 与工具调用的关系

- 需要事实依据时先用 `read`、`capabilitySearch`、`skillLoad` 等工具读取。
- 需要写入项目时使用 `write`、`edit` 或 `delete`，依赖 `workspace_patch` 审计。
- 工具调用结果可摘要给用户，但不要泄露与任务无关的内部细节。
